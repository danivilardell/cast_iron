# Covert Timestamped Commitments (CTC)

A Python implementation of the CTC primitive from the Cast Iron coercion-resistant e-voting paper (Sec. 4, Fig. 2).

A CTC lets a voter register a commitment on a public blockchain (the timestamping oracle TS) such that it

- is **covert**: the registration transaction looks like an ordinary balance-emptying transfer (the anonymity set is the set of such transactions, not all transactions; see paper Sec. 4.1 / App. D.2);
- is **timestamp-binding**: opening proves the content and its position `t = (s, i)` on the chain.

## Construction

Two algorithms (there is no Setup; the public parameters are secp256k1, the Poseidon2 instance and the chain's tx hash):

- **Commit(m; r) → t** — computes the nonce `c = H(m ‖ r)`, signs a single-use transaction that moves the key's entire balance with ECDSA nonce `c`, posts it, returns its position `t`. Locally stores `(m, r)`.
- **Open(m, r, t) → bool** — recomputes `c`, reads the record at `t`, and checks `r_σ == x([c]G)`. Public; no key needed.

### Hash (circuit-compatible)

`H` is Poseidon2 over the BN254 scalar field (width 2, 6 full / 50 partial rounds, Merkle–Damgård from state 0), implemented in `ctc/poseidon.py` and checked against gnark-crypto test vectors (`tests/vectors.json`, generated by `tests/gen_vectors/`). Following `voteropening.ComputeOpening`:

```
h1 = Poseidon(m ‖ r)
h2 = Poseidon(m ‖ r ‖ 1)
c  = (h1·2^254 + h2) mod n          # n = secp256k1 order
r_σ = x([c]G)
```

`m = (pk_i, σ_reg)` (paper Sec. 5.1) is a tuple of field elements, `r` is a field element (`commitment.encode_message` builds `m`). `c` is used **directly** as the ECDSA nonce. If `c = 0` or `x([c]G) ≥ n` (≈2⁻¹²⁸ each) `Commit` resamples `r` before posting. `commitment.compute_opening` also returns `r_σ` split into 128-bit halves and `entry_commitment` gives the record-tree leaf `Poseidon(1, pos, r_σ_hi, r_σ_lo)`.

## Registration walkthrough

What a voter's local registration client does to realise Sec. 4.1 / Fig. 2 (Tron USDT; see `main.py` for the runnable commit/open part):

1. **Credential.** Voter `v_i` holds a fresh voting key `(pk_i, sk_i)` and the signature `σ_reg = Sig.Sign(IC.sk, pk_i)`. The CTC message is `m = encode_message(pk_i, σ_reg)`.
2. **Rotating address.** Generate a fresh single-use Tron key (`tronpy.keys.PrivateKey.random()`). It is never reused: opening reveals it.
3. **Anonymous funding.** Send the new address `X` USDT (plus the TRX needed for energy) in an ordinary transfer that is *not* linkable to the voter, e.g. from a wallet or exchange withdrawal that is not tied to their identity, with the transfer itself submitted over an anonymous channel. This step is outside this package; the paper treats it as the anonymous-channel assumption.
4. **Commit.** Read the address's full USDT balance and commit with it as the amount, so the registration transaction empties the address:

   ```python
   chain = TronTRC20Blockchain(client, key_bytes, recipient, usdt_contract, amount=full_usdt_balance)
   ctc = CTC(chain)
   t_reg = ctc.commit(m)        # draws r, c = H(m ‖ r); signs transfer(recipient, amount) with nonce c; posts it
   m, r = ctc.get_opening(t_reg)
   ```

   Submit through an anonymous channel (e.g. Tor to the node). The transaction is an ordinary USDT transfer whose signature nonce happens to be `c`; `c` itself never appears on chain, only `r_σ = x([c]G)`.
5. **Store.** Keep `(m, r, t_reg)` (here `t_reg` is the Tron txid). Discard the one-time key; it is no longer funded and opening makes it recoverable.
6. **Vote and open.** Ballots carry `(pk_i, σ_reg, r, t_reg)`; the tallier / circuit recomputes `c` and checks `r_σ == x([c]G)` against the record at `t_reg`. Outside the circuit, `ctc.open(m, r, t_reg)` does the same check.

The package does not generate or fund the one-time key and does not compute the sweep amount (`amount` is the caller's); it supplies steps 4 and 6.

## Layout

```
ctc/
├── poseidon.py            # Poseidon2 / BN254, matches gnark-crypto
├── commitment.py          # c = H(m ‖ r) nonce derivation, r_σ, leaf helper
├── blockchain.py          # TS oracle ABC: post(nonce) → t, read(t) → signature r
├── ctc.py                 # Commit / Open
└── adapters/
    ├── mock_blockchain.py  # In-memory mock (records x([c]G))
    └── tron_blockchain.py  # Tron: TRX (TronNonceBlockchain) / TRC-20 (TronTRC20Blockchain)
tests/
├── vectors.json            # Go-generated vectors
└── gen_vectors/            # regenerate: cd tests/gen_vectors && GOFLAGS=-mod=mod go run . > ../vectors.json
```

## Tests

```
uv run pytest                                  # Tron tests run only if .env is set
uv run pytest --deselect tests/test_tron_ctc.py  # offline
```

The Tron tests broadcast real testnet transactions from the key in `.env`.

## Demo

`main.py` runs commit/open over a USDT transfer on Tron Nile. Create `.env` (never commit it):

```
TRON_TESTNET_NODE=https://nile.trongrid.io
TRON_PRIVATE_KEY=<64-hex private key, single-use, minimal funds>
TRON_RECIPIENT=<base58check address>
TRON_TRC20_CONTRACT=<USDT contract on Nile>
TRON_USDT_AMOUNT=1
TRON_OPEN_DELAY=30      # optional
```

## Dependencies

`tronpy[offline]`, `ecdsa`, `python-dotenv`, `eth-hash[pycryptodome]` (Keccak for Poseidon2 round keys).
